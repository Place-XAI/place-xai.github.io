An agentic artificially intelligent X-ray scientist

Zhantao Chen · Alexander N. Petsch · Aidan J. Israelski · Rajan Plumley · Lingjia Shen · Cong Wang · Cheng Peng · Yuan Ni · Arun Bansil · Sugata Chowdhury · Mingda Li · Jana B. Thayer · Vivek Thampy · Joshua J. Turner Published 2026-07-01 DOI 10.1038/s42256-026-01261-5 Source nature.com ↗
Core Conclusion

An off-the-shelf reasoning LLM, wrapped in structured tool use via the Model Context Protocol (MCP), can autonomously perform single-crystal sample alignment on a real synchrotron beamline — planning actions, issuing SPEC-style motor commands, reading detector images and scan plots, and iterating until the orientation matrix is determined. The agent was prepared entirely in an in-house virtual beamline and transferred unchanged in prompting and decision logic to BL17-2 at SSRL, where it discovered and self-corrected an unexpected ≈1.22° η motor offset. The contribution is not a new architecture but a demonstration that virtual-environment preparation plus tool-mediated closed-loop reasoning makes general-purpose LLMs deployable on scarce, safety-constrained, oversubscribed scientific instruments.

Why It Matters

  • Closes the last gap between "AI reasons" and "AI operates". Most agentic-science work stops at planning, code, or literature. Here the agent moves real motors on a real beamline and the physical outcome (a correct orientation matrix, verified against a third reflection) is the evaluation metric.
  • Sim-first is the practical route to expensive instruments. Beamtime is scarce and hazardous; training an agent on the machine is impossible. The paper shows that a laptop-runnable virtual beamline is enough to develop, debug and harden the whole agentic workflow before touching hardware — a template for any capital-intensive facility.
  • Adaptation, not automation. Scripted alignment breaks when the sample holder is uneven or a motor has a hidden offset. The agent detected the offset, reasoned about its cause, and reused the empirical correction on the next reflection — short-term experimental memory that fixed pipelines cannot express.
  • Safety is designed in, not bolted on. In the real run the LLM emitted Execute Command: [...] and a human relayed it verbatim: full autonomy of decision, zero autonomy of actuation. That is a reusable governance pattern for autonomy in high-consequence settings.
  • Fully open artifacts. Data and source code (virtual beamline + MCP server) are on Zenodo, making the whole loop reproducible without a synchrotron.

Core Data — Sources & Volume

Real instrument
Beamline BL17-2 at SSRL, SLAC National Accelerator Laboratory — a six-circle ("4S + 2D") diffractometer with four sample motors (ϕ, χ, η, μ) and two detector motors (δ, ν). Incident energy 16.0 keV (λ ≈ 0.7749 Å), sample on a copper holder, room temperature, ambient air.
Samples
Two single crystals: the magnetic Weyl semimetal Co3Sn2S2 (rhombohedral R3̄m, no. 166; hexagonal cell a = b ≈ 5.36 Å, c ≈ 13.02 Å) with broad peaks, and a high-quality single-crystal Si with extremely sharp peaks (Supplementary Note 8).
Crystal structure files
Materials Project structure used in the virtual experiments; a different, experimentally curated Crystallography Open Database (COD) structure used in the real experiment — deliberately, to show the workflow is agnostic to the crystallographic data source.
Simulated "data"
Generated by an in-house Python virtual beamline (runs on a laptop). Diffraction intensities computed with pymatgen, Gaussian broadening σQ = 0.026 Å⁻¹, non-isotropic stretch factors 1.0 / 1.5 / 0.75 along H / K / L, plus injected inactive & hot pixels and readout noise. Momentum transfer per detector pixel follows You's (1999) six-circle formalism.
Benchmark volume
Two LLMs × 10 independent runs each (Claude Sonnet 4, Gemini 2.5 Flash) under randomized hidden motor offsets Δη ~ N(0°, 0.5°), Δϕ ~ N(0°, 1.5°); the simulator secretly used a = b = 5.5 Å, c = 13.2 Å while the agent was told the nominal values. Additional Gemini 2.5 Flash scenario sweeps: baseline, larger motor offsets, multi-grain diffraction, reduced reasoning (512-token thinking budget), lowered temperature. Per-scenario run counts are shown in Fig. 2 parentheses rather than stated as a single number in text.
Success criteria
Alignment error ≤ 15° (angular deviation between predicted and true orientation matrices) and |cpred − ctrue| ≤ 0.01 Å. Most runs achieved alignment error < 5°; more than half achieved c-error < 0.01 Å.
Real-run coverage
Reference reflections (0, 0, 6) and (1, 0, 10) for Co3Sn2S2, verified with (2, 0, 14). Because of beamtime limits, real-beamline configurations were not systematically repeated — the authors state this explicitly and warn against reading the offset recovery as a statistically established capability.
Models & settings
Claude Opus 4 (real beamline, via Claude Desktop), Claude Sonnet 4 (temperature 1.0, top-P 0.7, top-K 5, 2,000-token thinking budget) and Gemini 2.5 Flash (temperature 1.00, top-P 0.95, top-K 40, "Auto" thinking budget) via LibreChat API access; max 100 agent steps, max output 8,192 tokens.

Core Methods

  • Agentic loop over an instrument, not a dataset: observe (terminal I/O, detector image, scan plot) → reason → issue a SPEC-style command → observe again, repeated until the orientation matrix is fixed. Stage transitions are decided by the model, not pre-scripted.
  • MCP as the hardware-abstraction layer: a purpose-built MCP server exposes execute_command plus auxiliary tools; in the virtual setting, "terminal commands" are keyword-parsed and routed to methods on a Python experiment object that holds persistent sample and diffractometer state.
  • Multimodal, human-like observation channel: the agent deliberately receives rendered images and plots — detector frames and scan curves with fitted peak centres overlaid — never raw numerical arrays, so it interprets the experiment much as a beamline scientist reading a screen would.
  • Virtual beamline as a physics simulator: Rsample = M·H·X·Φ and Rdetector = Π·Δ per You's six-circle formalism; Qc = (2π/λ)(k̂out − k̂in); intensities I(RsampleTQc) from pymatgen, degraded with broadening, anisotropic stretching, dead/hot pixels and readout noise so that images "look experimental."
  • In-context guidance instead of fine-tuning: a short prompt (working directory, expected outputs, key reminders) plus a long guidance prompt (tool documentation, alignment workflow), iteratively refined by watching failure modes in simulation. No weights are trained or adapted.
  • Two-reflection alignment protocol: setup → primary reflection search/optimization (η, χ, δ scans with ROI-specific integration: vertical-line ROI for χ/ϕ, horizontal-line ROI for δ, centre-area ROI for η) → secondary reflection with a wide ϕ scan to resolve in-plane orientation → register with or0/or1 and refine the lattice constant.
  • Quantitative evaluation: alignment error = arccos[(tr(RpredRtrueT) − 1)/2] and |cpred − ctrue|, with success thresholds 15° and 0.01 Å; ablations over reasoning budget, temperature, motor offset magnitude and multi-grain confusion.
  • Human-as-actuator safety relay: for the first real deployment the model's exact command string was executed unmodified by a person, preserving decision autonomy while satisfying facility interlock/radiation policy.

① Turn the hand-tuned guidance prompt into an optimized, auditable artifact

Extending this paperThe paper is candid that its long guidance prompt was written by hand and refined by watching failure modes in the simulator — the single least reproducible component of an otherwise open pipeline, and the one the authors themselves flag as the barrier to porting the agent to a new beamline ("meta-agents that can assist in constructing and refining instrument-specific guidance prompts"). The concrete extension: treat the guidance prompt as a differentiable-by-feedback parameter and optimize it inside the virtual beamline against the paper's own scalar objectives (alignment error, |Δc|, tool-call count), then freeze and version the winning prompt as a citable artifact alongside the Zenodo code. Because the simulator is free to run, this converts prompt engineering from craft into a measurable optimization with a held-out set of crystal systems (cubic Si vs hexagonal Co3Sn2S2 vs unseen monoclinic cells).

Added value to my researchMy workflows increasingly involve LLM-mediated steps — literature screening for systematic accessibility reviews, POI category harmonization, code generation for MGWR/2SFCA pipelines — where the prompt is currently an undocumented dependency that silently changes results between reruns. Adopting this paper's discipline (prompt as versioned, benchmarked, Zenodo-deposited artifact, optimized against a task metric on a synthetic environment) gives my FAIR/open-science line a concrete practice: prompt provenance as part of geospatial reproducibility, with a synthetic city-generator playing the role their virtual beamline plays.

② Stress-test the agent's reliability curve before granting actuation autonomy

Extending this paperThe benchmark is ten runs per model on one task with one material, and the striking real-beamline behaviour — spotting and reusing the ≈1.22° η offset — happened in a handful of unrepeated trials, as the authors carefully state. The natural extension is a reliability study rather than a capability demo: sweep model scale and reasoning budget (they already saw degradation at a 512-token thinking budget) against a difficulty ladder of injected pathologies — multi-grain samples, twinned crystals, saturated detectors, motors parked at their limits, deliberately wrong lattice files — and chart where confident-but-wrong behaviour emerges. That reliability curve, not the success rate, is what determines whether the human relay can ever be removed, and it directly answers the known failure pattern where more capable, more instructable models fail less predictably.

Added value to my researchExactly the missing evidence layer for LLM-assisted health-geography work: before letting an agent delineate service areas or classify facility types at scale, I need its error profile under distribution shift (rural vs urban POI density, sparse mobile-phone coverage, non-English facility names), not its average accuracy. This paper hands me a template — synthetic ground-truth environment, injected pathologies, success threshold, per-scenario box plots — for an "agent reliability card" that could accompany any GeoAI accessibility pipeline I publish.

③ Generalize "virtual environment first, real instrument second" into a portable sim-to-real protocol

Extending this paperThe paper's deepest transferable claim is methodological: a laptop-scale simulator, faithful only in the ways the agent perceives (rendered plots, noisy images, realistic motor limits copied from BL17-2), is sufficient to develop an agent that transfers with prompting and decision logic unchanged. Extending it means quantifying that transfer instead of asserting it: build a fidelity-ablation ladder — remove hot pixels, remove readout noise, remove the anisotropic peak stretch, idealize motor limits — and measure how each removal degrades real-beamline (or held-out high-fidelity-sim) success. The result would be a reusable recipe stating the minimum simulator fidelity needed per perception channel, letting other facilities build their virtual twin at the cheapest sufficient level rather than guessing.

Added value to my researchThis is the same question I face in agent-based modeling of urban service use: how faithful must a synthetic city be before behavioural rules calibrated in it survive contact with real GPS trajectories and mobile-phone records? Borrowing the fidelity-ablation ladder gives my ABM and digital-twin work a principled calibration protocol — ablate synthetic road-network detail, POI mislabeling, population-grid resolution — and turns "our simulation is realistic enough" into a measured statement.

④ Move from a single-task agent to a scientific campaign planner with memory

Extending this paperThe demonstrated task, orientation-matrix determination, is a prerequisite — the agent stops exactly where the science begins. The extension that would raise this from "autonomous alignment" to "autonomous experiment" is to chain alignment into hypothesis-driven measurement campaigns: after registering the reference reflections, let the agent choose which reciprocal-space regions and temperatures to measure, allocate remaining beamtime under an explicit budget, and revise the plan as peaks appear or vanish. That requires two things the current system lacks — persistent cross-session memory (the η-offset insight survived within a session but nothing carries to the next sample) and an information-gain objective for deciding what to measure next, connecting the agentic layer back to the Bayesian experimental-design literature the introduction cites but does not use.

Added value to my researchMaps cleanly onto adaptive spatial sampling: an agent that decides where to survey next for mental-health service availability or EV-charging demand, under a fixed fieldwork budget, choosing sites by expected reduction in accessibility-estimate variance. The paper's structure — tool-mediated actions, persistent state object, explicit stopping criterion — is directly reusable as the control skeleton for a spatial active-sampling agent.

⑤ Formalize the human-relay pattern into a graded autonomy ladder for high-consequence instruments

Extending this paperThe safety design here is elegant but binary and undocumented as a contribution: the LLM decides everything, a human types everything. The extension is to make the relay a typed, machine-checkable action gate — replace keyword parsing of "Execute Command: [...]" (which the authors themselves flag as brittle) with schema-constrained outputs, then attach a risk classifier per command: motor moves inside verified soft limits auto-execute, moves near collision envelopes or shutter/attenuator changes require confirmation, anything unparsable halts. Logging every proposed-vs-executed command yields an empirical autonomy ladder — the fraction of commands safely auto-executable — that a facility safety committee can actually act on, and generalizes the pattern beyond this one beamline.

Added value to my researchThe same graded-gate architecture is what public-health-facing GeoAI needs: an agent may freely recompute catchment areas or re-run an accessibility model, but recommendations that would relocate a clinic, reallocate telehealth capacity, or site a charging station must pass an equity-impact gate before reaching a decision-maker. Borrowing this paper's "full decision autonomy, gated actuation, complete audit log" split gives my policy-translational work a defensible governance design rather than an ad-hoc disclaimer.
